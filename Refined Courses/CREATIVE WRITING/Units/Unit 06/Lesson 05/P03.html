Lesson: Prepare the Reader’s Digital Experience

Step 1 — Lock Meaning Before Formatting

Confirm that high-impact revision is complete. Save a clearly labeled content-approved version. Formatting may clarify presentation, but it must not silently rewrite the author’s meaning.

Step 2 — Match Format to Genre

GenrePreserveTest
Fiction/essayParagraphing, scene breaks, emphasisLong-page readability
PoetryLineation, indentation, stanza spaceSmall-screen wrapping
ScriptSpeaker labels, cues, dialogue spacingScanning during performance

Step 3 — Build Hierarchy

  1. Use one clear title and author line.
  2. Use headings only when the genre requires sections.
  3. Keep body type readable and consistent.
  4. Use white space to group, not decorate.
  5. Use bold and italics sparingly and meaningfully.

Pause and Choose: Preserve Genre Meaning

A poetry layout wraps badly on a phone and changes where key lines break. Which response is strongest?

A. Test a responsive layout or alternate file format that preserves intentional lineation across likely devices.
Stronger choice. In poetry, line breaks carry meaning and rhythm. Digital preparation must protect that craft decision while keeping the work readable.
B. Ignore the wrapping because formatting never affects meaning.
Weaker choice. Digital display can alter emphasis, pace, and ambiguity. A source file that looks correct on one screen is not sufficient evidence.

Retry: If your first choice is weaker, close it and select the other choice before continuing. Compare both explanations so you can name why the stronger answer works.

Step 4 — Design for Access

  • Use sufficient text/background contrast.
  • Do not communicate meaning through color alone.
  • Add alternative text for meaningful images.
  • Provide transcripts for audio and captions for video.
  • Use descriptive links and logical heading order.
  • Test keyboard navigation and reading order when the platform permits.

Step 5 — Proof in Layers

Make separate passes for content accuracy, conventions, visual consistency, links/media, rights/privacy, accessibility, and device display. A single fast reread misses category-specific errors.

Pause and Choose: Verify the Final File

The editable document is correct, but the exported PDF drops an image caption and breaks a link. Is the work publication-ready?

A. Yes. Checking the source document is enough.
Weaker choice. Readers receive the exported artifact, not the editor view. Errors introduced during export are still publication errors.
B. No. Repair the caption and link, export again, and preflight the actual final file.
Stronger choice. Final-file verification tests the reader’s real experience, including accessibility, media, navigation, and format stability.

Retry: If your first choice is weaker, close it and select the other choice before continuing. Compare both explanations so you can name why the stronger answer works.

Step 6 — Preflight

Open the final exported file, not only the source. Confirm file name, page order, embedded media, working links, metadata, permissions, and a stable backup.
