Lesson: Integrating a Publication-Ready Communication

The Integrated Workflow

  1. Interpret the brief: define audience, purpose, claim, format, and constraints.
  2. Map the evidence: connect every major claim to credible, correctly represented support.
  3. Design the communication path: sequence ideas so a reader, viewer, or listener can follow the reasoning.
  4. Assign each medium a job: use media to clarify, demonstrate, compare, document, or create appropriate emphasis.
  5. Draft and synthesize: integrate sources into your own reasoning rather than stacking quotations.
  6. Audit: check editorial quality, source integrity, permissions, accessibility, privacy, and usability.
  7. Test and revise: observe an intended user, record problems, and make targeted changes.
  8. Release and reflect: complete credits, approvals, version records, fallback content, and rationale.

Example 1 — Historical Podcast

A student claims that a flood-control project divided a neighborhood. Oral histories reveal lived experience, a map shows the physical division, and council minutes verify the decision. The media are coherent because each contributes different evidence. The student must distinguish memory from documented fact and provide a transcript.

Example 2 — Scientific Explainer

A visual explainer about urban heat uses temperature data, a short expert quotation, and paired photographs. A decorative animation is removed because it distracts from the comparison; a labeled chart and accessible text summary replace it.

Example 3 — Literary Exhibition

An online exhibition argues that a novel’s recurring doorway imagery marks changes in power. Brief quotations, close reading, and a visual motif support the claim. The curator adds context so images do not merely repeat the written analysis.

Common Mistakes

  • Beginning production before defining the communication brief.
  • Adding media for decoration rather than evidence or explanation.
  • Treating all sources as equally credible or removing qualifications from a source.
  • Using captions or alt text that repeat a filename instead of conveying meaning.
  • Calling a project “finished” without user testing, permissions, credits, or a change log.
