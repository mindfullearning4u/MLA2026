# QA and Publishing

## Required verification

Before reporting completion, verify:

- unit and lesson names and counts match all approved mapping documents;
- course overview counts and titles match the Moodle dashboard;
- every activity is in the correct unit and order;
- release restrictions reference the intended preceding activity;
- every Savvas button opens the exact required resource;
- lesson pages state exact directions, stopping points, evidence, and help information;
- pretest, quiz, unit-assessment, attempt, randomization, and mastery settings are correct;
- question-bank counts meet the specification;
- rubrics are lesson-specific and usable by the TOR;
- gradebook categories and weights are correct;
- student preview/navigation works;
- GitHub contains only the intended current documents and no accidental replacements.

Use visible saved-state evidence. Reopen representative and high-risk items after saving. For structural changes, inspect every affected dependency rather than sampling.

## GitHub discipline

- Treat the repository as the authoritative portable source.
- Read the current branch and status before editing.
- Preserve unrelated changes.
- Stage only intended files.
- Use a concise commit describing the actual change.
- Push only after validation.
- Report the branch, commit, changed paths, checks, and any unresolved items.

Never state that a commit, push, Moodle save, or live configuration succeeded unless the resulting state was verified.
