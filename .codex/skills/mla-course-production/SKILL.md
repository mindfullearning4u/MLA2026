# MLA Course Production

## Start every task

1. Read the repository `AGENTS.md` and obey its locked-content rules.
2. Identify the course, approved publisher/program, current mapping documents, and requested production phase.
3. Treat GitHub as the authoritative record. Inspect the applicable course folder before drafting or editing.
4. Preserve user changes and existing approved content. Do not infer permission for unrelated edits.
5. Verify live, changeable facts in the relevant authoritative source before using them.

## Load only the references needed

- For crosswalks, standards, unit design, or lesson mapping, read [curriculum-mapping.md](references/curriculum-mapping.md).
- For Moodle dashboards, lesson pages, release restrictions, or Savvas links, read [moodle-production.md](references/moodle-production.md).
- For pretests, quizzes, submissions, rubrics, unit assessments, or gradebook configuration, read [assessment-and-gradebook.md](references/assessment-and-gradebook.md).
- Before declaring work complete, read [qa-and-publishing.md](references/qa-and-publishing.md).
- For student-facing HTML, copy and adapt [lesson-page-template.html](assets/lesson-page-template.html). Keep inline CSS for Moodle compatibility.
- For any Moodle dashboard, orientation, or lesson-page task, read [VISUAL_REFERENCE_INDEX.md](assets/visual-references/VISUAL_REFERENCE_INDEX.md) and inspect every applicable screenshot before building or auditing.

## Operating principles

- Let subject matter, standards depth, and approved resources determine unit and lesson counts. Never force a standard count.
- Give every unit and lesson a clear content-specific name.
- Do not label a final lesson as synthesis or “putting it all together” unless the content genuinely requires synthesis.
- Use exact resource-level Savvas URLs, not dashboard, program, or generic landing links.
- Keep Moodle as MLA's official evidence and grade record.
- Build for asynchronous, mastery-based learning with Teacher of Record support.
- Separate notebook evidence, checkpoint evidence, quizzes, and unit assessments according to their defined purposes.
- Make student directions explicit: what to open, what to complete, where to stop, what evidence to submit, and where to get help.
- Never claim a Moodle, Savvas, GitHub, restriction, link, or gradebook change was completed without verifying the saved state.

## Default workflow

1. Inspect sources and current repository state.
2. Produce or update the standards crosswalk.
3. Produce the mapping framework, unit mapping, lesson mapping, and resource/lab mapping.
4. Reconcile the Moodle dashboard to the approved unit and lesson architecture.
5. Configure sequential release restrictions.
6. Build student-facing pages with exact publisher links and evidence directions.
7. Build assessments and rubrics from approved course content.
8. Configure and verify gradebook weights.
9. Audit names, counts, links, restrictions, navigation, assessment settings, and saved state.
10. Commit only the intended files and report exactly what changed.
